# Member Comparison Edit

## Functional requirements

When comparing currently saved members list (on the left) against the member generated by the new definition the user
should be able to add a member from the left to the definition

there needs to be a right arrow or equivalent indicator that the user can click

Only members flagged as removed (saved members that the new definition does not generate) show the arrow, as unchanged
members are already generated by the definition

## Technical requirements

A new helper method (addMemberToDefinition in MemberComparison.ts) will add to the definition

This will take the member to add (ComparedMember) and the definition being edited, i.e. `build.value` in ECLBuilder.
The definition is mutated in place, so the method returns void

The query passed to MembersComparison (props.query) is an optimised clone of `build.value` (wrapped in
descendantsOrSelfOf when include subtypes is checked), so it must not be the target of the edit. Instead
MembersComparison emits an `addMember` event to ECLBuilder, which calls addMemberToDefinition with `build.value` and
then rebuilds the comparison query. MembersComparison watches props.query and reloads the members when it changes

Where the member cannot be added to an existing clause, the root's keys are moved into a child clause and the root
becomes a boolean clause (e.g. `{ or: [<existing>, <member>] }`), as the root object itself cannot be replaced

The method stub is required but should not be implemented yet as inserting the member into the query definition will
require the creation of the correct boolean clause
